# 故障速查台账（2026-10-20 ~ 2026-10-21 全部实证记录）

> 本页记录当时的现象和处理结果，当前可用性待现场验收。
> 用法：遇到问题先按「症状」找行，再照「解法」处理；「根因」帮你判断是不是同一个问题。
> 标记说明：✅ 已结案（根因确认、解法验证）；🔶 已缓解（有兜底，根因未完全确认）；⏳ 未结案（处理中）。

## 一、ComfyUI 后端与局域网链路

补充记录中，10 月 20 日的启动问题曾处理，2026-10-27 后曾报告 8188 无响应。2026-11-19 15:05（Asia/Shanghai，CST），Mac 经 Tailscale 访问 8188，首页和 `/system_stats` 均返回 HTTP 200。Windows 本机 8189、portproxy 内部配置、工作流与模型生成均未验证。

### 1. ✅ 后端绑 8188 起不来，报 winerror 10013
- **症状**：手动启动后端时绑定 8188 失败，`winerror 10013`（地址已被占用/禁止访问）。
- **根因**：IP Helper 服务（iphlpsvc）占用了 8188——它也是后面 portproxy 转发要依赖的服务，杀不得。
- **解法**：后端改绑 **8189**，对外用 portproxy `8188 → localhost:8189`。此后成为固定拓扑，不要试图改回。

### 2. ✅ 后端起来了，但报一堆 Missing Models
- **症状**：局域网打开 ComfyUI，工作流里模型全红/缺失。
- **根因**：手动后端只读**安装目录**下的 `models`，而 Desktop 的模型在 **Shared** 目录，两套目录不是同一份。
- **解法**：把安装目录 `models` 下 `diffusion_models / loras / vae / text_encoders` 四个目录改为指向 Shared 对应目录的**目录联接**（原目录改名 `*_bak` 备份）；前端再报缺失就在 Issues 面板点 **Refresh**。

### 3. ✅ 不要用 --base-directory
- **症状**：加了 `--base-directory` 后目录关系错乱、素材找不到。
- **解法**：启动参数只用 `--port 8189 --input-directory <Shared>\input --output-directory <Shared>\output`，写在核心脚本 `comfy-backend.ps1` 里固定下来。

### 4. 🔶 后端静默消失（无崩溃、无人停）
- **症状**：2026-10-21 10:57 验活还在，11:40 发现进程已消失；control 日志无 stop 记录、系统无崩溃事件、后端日志结尾是正常启动输出。
- **根因**：**未查明**（已排除：人为 stop、系统崩溃事件、看门狗误杀——当时还没有看门狗）。
- **解法/兜底**：立即重启恢复；新增 **看门狗计划任务**（每 5 分钟幂等 start）兜底，任务依赖交互式登录，检查端口监听，实际恢复时间与可用性需另验。下次复发时查：后端日志最后时间戳前后的系统事件（会话注销/切换、电源事件 566）与 GPU 驱动日志。

### 5. ✅ SSH 里用 Start-Process 拉起的后端活不下来
- **症状**：助手经 SSH 用 Start-Process 启动 python，命令返回成功，进程随即消失。
- **根因**：SSH 会话结束时其子进程被一并清理。
- **解法**：核心脚本改用 **WMI `Win32_Process.Create`** 启动后端，规避当时的会话退出问题。通过 `comfy-backend.ps1` 管理后端，断线后复查 HTTP 与日志。

### 6. ✅ 助手误判「ComfyUI 死了」——VM 的 curl 被代理劫持
- **症状**：助手在自己环境里 curl `<Windows Tailscale IP>:8188` 得到空响应（curl 52），一度怀疑通道故障。
- **根因**：助手 VM 的 `http_proxy` 环境变量把请求送去了出口代理，tailnet 地址根本没被真正访问；加 `--noproxy` 又没有直达路由。
- **解法**：先在 Windows 检查 `http://localhost:8189/system_stats`，再从 Mac 验证 8188 的局域网和 Tailnet 入口。助手 VM 的代理报错仅反映该请求的路径。

### 7. ✅ ComfyUI Desktop 里找不到模型目录
- **症状**：Desktop 版（v0.42.1）左上角菜单里没有 Help → Open Folder，找不到模型该放哪。
- **解法**：在文件资源管理器里搜索一个已知的模型文件名，右键「打开文件所在的位置」即达 `diffusion_models`。

### 8. ✅ 给 ComfyUI 操作指令前，先核验节点定义
- **症状**：助手凭印象说某个节点有某参数、某端口是某类型，结果界面上根本没有，让用户白折腾。
- **教训**：给 ComfyUI 操作指令前，**必须先核验节点定义/端口类型**，不许凭印象。已写入长期操作规范。

### 9. ✅ RDP 登录连拒 3 次：微软账号不认 PIN
- **症状**：用主账号连 RDP，密码/PIN 都不对，安全日志事件 4625、子状态 `0xC000006A`（密码错误），来源确认是 Mac。
- **根因**：主账号是**微软账号**，RDP 只认微软账号密码、不认 PIN，且不应把微软密码输进其他设备。
- **解法**：在 Windows 本机新建**专用本地账号 `rdp`**（密码本机自设），加入 Administrators + Remote Desktop Users；RDP 一律用它。本机登录照常用原账号 + PIN。

### 10. ✅ 存了凭据还是每次弹密码框
- **症状**：Windows App 里明明存了凭据，连接时仍要手输。
- **根因**：只在「设置 → 凭据」里存还不够；PC 的「配置…」里凭据下拉还停在「在需要时询问」。
- **解法**：在该 PC 的配置里把凭据**改选为已存的那条**并保存，之后双击免密直连。

### 11. ✅ 证书警告 + 勾选框点不中
- **症状**：首连弹自签名证书警告；「始终信任」勾选框用坐标点了两次没中。
- **说明**：弹框本身证明已摸到 3389。勾选框在无障碍树里没有元素，用视觉定位点中；该对话框默认按钮可用回车触发「继续」。
- **解法**：勾上「始终信任 <主机名>」后继续；之后不再弹。

### 12. ✅ rdp 桌面上少东西（两起，同一根因）
- **症状**：①rdp 桌面找不到模式工具那几个 .bat；②rdp 桌面比主账号少了一大批软件图标、也没有 Tailscale 图标。
- **根因**：文件在**主账号个人桌面**，rdp 是独立账号看不见；Tailscale 客户端其实是全用户自启、在 rdp 会话里也在运行，只是托盘图标被收进了 `^` 隐藏区、桌面上没图标。
- **解法**：工具与应用快捷方式统一放 **`C:\Users\Public\Desktop`（公共桌面）**：4 个 .bat、35 个应用快捷方式、微信多开、Tailscale 快捷方式全部归位，两个账号桌面一致；个人文档不挪。

## 三、Tailscale 与通道

### 13. ✅ Tailscale 界面报 "already in use by <主机名>\<主账号>"
- **症状**：在 rdp 会话里打开 Tailscale 界面，弹错：已被 `<主机名>\<主账号>` 占用。
- **根因**：Tailscale 的 Windows 界面程序在同一台机器上**只允许一个用户会话接管**；主账号断开的会话里那个界面还占着。
- **解法**：关掉占用会话里的界面进程（只关 GUI、不停 tailscaled 服务，不断网），本会话界面即可接管。注意：之后若主账号在本地登录并打开界面，占用的会反过来——同一时刻以先开者为准，属产品规则不是故障。

### 14. ✅ 通道中断：Windows 主机离开了 tailnet（2026-10-21 12:47–15:51，已结案）
- **症状**：12:47 前后助手经 SSH 的命令先变慢/返回不全，之后 SSH 持续失败（`proxy closed connection`）；同时发现 Mac 上 Tailscale 应用是关着的、打开显示 **Not Connected**。
- **定位过程（已确认）**：15:43 用户在 Mac 上手动重连成功后，设备列表里 `Windows 主机` 仍不在线 → 断点在 Windows 主机侧（主机离开了 tailnet）；15:51 用户在主机上手动重连 Tailscale，SSH 随即恢复。故障前最后的成功操作是远程关掉主账号会话的 Tailscale 界面进程（条目 15），与中断时间相邻，但**因果未证实**，主机为何离开 tailnet 未查明。
- **影响面**：仅远程通道；主机本地服务未停——恢复后验活显示 ComfyUI 后端断网期间一直在跑（自启与看门狗不依赖网络）。
- **恢复后实测**：SSH 执行、文件传输、ComfyUI 操控三件套闭环。
- **经验**：①通道故障按「Mac 的 Tailscale 状态 → 设备列表看目标机是否在线 → 主机本地确认」分段定位；②当时的 SSH 长连接出现 broken pipe，可用短连接轮询后台任务及日志；③ComfyUI 的 SaveVideo 在 history 的 outputs 里挂在 `images` 键下（不是 `videos`）。

### 15. ✅ Mac 的远程控制通道离线
- **症状**：2026-10-21 11:14–12:03 助手对 Mac 的控制通道离线约 49 分钟。
- **解法**：在 Mac 上完全退出远程控制应用（⌘Q）并重开，通道恢复。以后助手长时间点不动 Mac 时，先想到这一招。

### 16. ✅ Mac 自启复选框不回显
- **症状**：Tailscale 应用内「Launch at login」勾了也不显示勾上。
- **根因**：该应用的显示 bug；系统层面其实已生效。
- **解法**：以「系统设置 → 通用 → 登录项」列表为准，列表里有 Tailscale 即已自启，别再纠结应用内复选框。

## 四、使用习惯类（不是故障，但容易误会）

### 17. 文件不能跨桌面直接粘贴（Mac 错误 -43）
- 在远程会话复制文件、回 Mac 粘贴报 **错误 -43**：Mac 版 Windows App 的文件剪贴板是虚拟占位，取不到实体。**正解是文件夹重定向通道**（此电脑 → 网络位置 → 重定向文件夹），文字/图片粘贴不受影响。

### 18. 远程登录会顶掉本机会话
- 用 rdp 远程登录时，本机屏幕会回到登录界面——同一账号同一时刻只有一个交互会话，正常现象。反过来在本地登录，也会把远程会话顶成断开。

### 19. Mac 与 Windows 之间传文件别用「直接粘贴」
- 已实测可用的只有：文件夹重定向（最稳）、Taildrop、让助手走 SSH 搬运。直接粘贴文件这条路在本环境就是不通，别反复试。

## 五、维护约定（从这些坑里提炼的规矩）

1. **报错协议**：工具出错，用户只说一句「报错了」，助手自己读日志处理；日志与工具同目录。
2. **工具母本唯一**：母本随工具包保存；任何修改先改母本，再同步到公共桌面等落地位置，并校验一致。
3. **助手给 ComfyUI 指令前先核验节点/端口定义**（条目 8 的教训）。
4. **分层验活**，主机检查 8189，Mac 检查 8188（条目 6）。
5. **通道类故障先分段定位**：Mac 的 Tailscale 状态 → 设备列表看目标机在线与否 → 再决定修哪一段（条目 14 的路径）。
